            Come creare il token (5 minuti)
            
          
              
        1. Modo semplice, token classico. Apri questo link (se GitHub chiede di accedere, accedi):
          
                github.com/settings/tokens/new
          
                Si apre la pagina New personal access token (classic) con già spuntate le caselle
                repo e workflow: servono entrambe.
          2. 
              
        2. In Expiration scegli 90 days. Quando scade ne crei un altro nello stesso modo.
          3. 
              
        3. Scorri in fondo e premi Generate token.
          4. 
              
        4. Copia il codice che inizia con ghp_. GitHub lo mostra una volta sola:
                se chiudi la pagina prima di copiarlo devi crearne un altro.
          5. 
              
        5. Incollalo nel campo qui sopra e premi Salva e verifica. Deve comparire «Collegato come …».
          6. 
              
        6. In alternativa, token fine-grained (più restrittivo):
                github.com/settings/personal-access-tokens/new
                → Repository access: All repositories → Permissions, sezione Repository, metti
                Read and write a: Actions, Administration (serve solo per creare i repository),
                Contents, Workflows. Metadata si attiva da solo.
          7. 
              
        7. Se l'app Pubblica ha già un token salvato in questo browser, Crea APK lo trova e lo usa.
                Se però manca qualche permesso tra quelli sopra, qui ti viene detto quale.
          8.

          6Guida passo-passo
          
    
          
      
          
        A · Tutto automatico dal telefono (consigliato)
        
            
          
          1. Una volta sola: crea il token in Impostazioni → 1 · Accesso a GitHub
            (istruzioni in «Come creare il token»). Per gli APK servono i permessi repo e workflow.
            2. 
          
          2. Carica lo script o lo ZIP del progetto (punto 1) e controlla che l'analisi (punto 2) non segnali errori rossi.
            3. 
          
          3. Nel punto 5 controlla il nome del repository. Viene proposto tuonome/:
            se non esiste viene creato. Usa un repository solo per questa app.
            4. 
          
          4. Premi Pubblica su GitHub e compila. Vedi i passaggi uno per uno; poi parte la compilazione con il
            tempo trascorso. La prima volta servono 20–40 minuti, le successive meno.
            5. 
          
          5. Quando finisce compare il riquadro verde Scarica APK. Tocca, apri il file scaricato e installa.
            La prima volta Android chiede di consentire «Installa app sconosciute» al browser: consentilo.
            6. 
          
          6. Per aggiornare: modifica lo script qui e premi di nuovo lo stesso pulsante. Vengono inviati solo i file
            cambiati, la versione sale da sola e la nuova app si installa sopra la vecchia senza perdere i dati.
            7. 
          
          7. Se fallisce: qui compaiono il passaggio che si è fermato, le ultime righe del log con il pulsante
            Copia il log e, se possibile, un suggerimento. Incolla il log a Claude.
            8. 
        
          
      
          
      
          
        A2 · A mano: ZIP + GitHub (o la tua app Pubblica)
        
            
          
          1. Scarica lo ZIP con il pulsante del punto 4. Finisce nella cartella Download.
            2. 
          
          2. Crea un repository GitHub nuovo, vuoto. Come nome usa il nome pacchetto ().
            Puoi crearlo con la tua app Pubblica oppure da github.com → pulsante + → New repository.
            Pubblico: compilazioni senza limiti. Privato: hai un numero di minuti gratuiti al mese
            (una compilazione completa ne usa circa 20–40).
            3. 
          
          3. Carica il contenuto dello ZIP nel repository. Con la voce 🚀 Pubblica su GitHub del menu: scegli il repository, seleziona lo ZIP, pubblica.
            In Pubblica imposta prima Impostazioni → Regole → Workflow GitHub su Includi le modifiche,
            altrimenti il file della compilazione non viene inviato.
            Importante: deve arrivare anche il file .github/workflows/build-apk.yml.
            La cartella .github inizia con un punto, quindi molti file manager la nascondono: è normale, nello ZIP c'è.
            4. 
          
          4. La compilazione parte da sola appena i file arrivano su GitHub.
            Apri il repository → scheda Actions → vedi "Build APK" con un pallino giallo = in corso.
            La prima volta dura 20–40 minuti perché scarica gli strumenti Android (SDK e NDK);
            le volte successive è più rapida grazie alla cache.
            5. 
          
          5. Pallino verde = APK pronto. Torna alla pagina principale del repository → sezione Releases
            (sul telefono è in fondo alla pagina) → apri "APK build N" → tocca il file .apk per scaricarlo.
            6. 
          
          6. Installa: apri il file scaricato. Android chiede di consentire "Installa app sconosciute"
            all'app da cui lo apri (browser o file manager): consentilo solo a quella.
            Play Protect può segnalare un'app sconosciuta: succede a tutte le app non scaricate dal Play Store.
            7. 
          
          7. Aggiornare l'app: modifica i file nella cartella progetto/ del repository (o ripubblica un nuovo ZIP)
            e la compilazione riparte da sola. Al primo giro il workflow crea la cartella firma/
            con la chiave di firma: non cancellarla, è ciò che permette di installare la nuova versione
            sopra la vecchia senza perdere i dati. Se la cancelli, dovrai disinstallare l'app prima di reinstallarla.
            8. 
          
          8. Se il pallino diventa rosso: tocca la compilazione fallita → passaggio Compila APK →
            scorri fino in fondo, copia le ultime 50 righe del log e incollale a Claude.
            9. 
        
          
      
          
      
          
        B · Su un PC Linux o Windows con WSL (Ubuntu)
        
            
          
          1. Estrai lo ZIP in una cartella e apri il terminale in quella cartella.
            2. 
          
          2. Installa gli strumenti di sistema (una volta sola):

            sudo apt update
sudo apt install -y git zip unzip openjdk-17-jdk python3-pip python3-venv \
  autoconf automake libtool pkg-config zlib1g-dev libncurses-dev \
  libffi-dev libssl-dev cmake build-essential
            3. 
          
          3. Crea un ambiente Python separato (sulle Ubuntu recenti pip fuori da un ambiente è bloccato):

            python3 -m venv ~/venv-buildozer
source ~/venv-buildozer/bin/activate
pip install --upgrade buildozer "cython==0.29.33" setuptools
            4. 
          
          4. Compila:

            buildozer android debug
            
            L'APK compare nella cartella bin/.
            5. 
        
          
      
          
      
          
        Cosa fa l'app generata
        
            
          
          1. Il tuo script o progetto resta intatto nella cartella progetto/ (sottocartelle comprese)
            e il file di avvio viene eseguito come con python file.py. Anche un tuo main.py va bene:
            non si scontra con quello della console.
            2. 
          
          2. print() → riquadro di testo (selezionabile, con pulsante Copia). input() → campo di testo + Invio.
            3. 
          
          3. Colori ANSI rimossi; os.system("clear") e \033[2J puliscono lo schermo.
            4. 
          
          4. Ferma interrompe lo script anche in un ciclo infinito; Esegui lo rilancia.
            5. 
          
          5. Dati che non si perdono: Android cancella e riestrae la cartella dell'app a ogni aggiornamento.
            Per questo lo script lavora in una cartella dati separata: al primo avvio vi vengono copiati i file
            di dati del progetto (JSON, YAML, CSV…) e ciò che lo script salva con percorsi relativi resta lì anche
            dopo gli aggiornamenti. Se in una nuova versione cambi un file di dati che lo script non ha mai modificato,
            arriva la versione nuova; se lo script l'ha modificato, resta la sua copia. Il percorso è in
            os.environ["CREA_APK_DATI"]. Tutto si cancella solo disinstallando l'app.
            6. 
          
          6. File e cartelle che iniziano con il punto (es. .env) non entrano nell'APK: Buildozer li salta sempre.
            7. 
        
          
      
          
    
          
  
          


          



          
  
          
    
          1 · Accesso a GitHub
          
    
          Il token resta nel browser di questo dispositivo. La pagina parla solo con api.github.com (lo impone anche il browser).
          
    
          ⚠ Se apri questa pagina da …github.io, tutte le tue app su quel dominio condividono la memoria del browser. Più sicuro: aprila come file salvato sul telefono, oppure non far ricordare il token.
          
    
    
    
    
    
    
          
      
      
    
          
    
          
    
          
      Come creare il token
      
            
        
          1. GitHub → Impostazioni → Sviluppatore → Token di accesso personali → Fine-grained tokens → Genera.
            2. 
        
          2. Repository: «Only select repositories» e scegli quelli che pubblichi.
            3. 
        
          3. Permessi: Contents → Read and write. Aggiungi Workflows solo se vuoi modificare i workflow, Pages per attivare il sito.
            4. 
        
          4. Per creare o eliminare repository serve un token classico con repo e delete_repo.
            5. 
        
          5. Imposta una scadenza breve e incolla il token qui.
            6. 
        
          6. Per creare APK (voce 📱 del menu) servono anche Workflows e Actions in «Read and write»
          e, per far creare i repository, Administration. Più semplice: un token classico con repo e workflow,
          crealo da qui
          (le due caselle sono già spuntate; scegli la scadenza, premi «Generate token», copia il codice ghp_… e incollalo sopra).
            7.

      Cosa fa, e cosa no, rispetto a pubblica di Termux
      
              
        
            • Pubblica: stessi controlli dello script (percorsi pericolosi, collegamenti simbolici, file .env, versione, submodule), più il blocco di chiavi e credenziali (.keystore, .jks, .pem, .key, chiavi SSH, credentials.json, token.json, client_secret*.json). Se lo ZIP contiene solo una cartella che esiste già su GitHub (es. docs), viene aggiornata solo quella. Differenze: i file d'esempio .env.example, .env.sample, .env.template, .env.dist vengono pubblicati; il controllo «versione più vecchia» vale per ogni progetto con versione.json (per Scheda Botanica il file è obbligatorio). ZIP completo = sostituzione con rimozioni; ZIP con __patch_only__.txt e file sciolti = solo aggiunte e modifiche. Un solo commit, tutto o niente.
              • 
        
            • Google Drive: una pagina web non può leggere Drive da sola: scegli lo ZIP dal selettore di Android (che apre Drive). Per copiare su Drive scarica lo ZIP dai Collegamenti.

            • Recupera invio rifiutato: non serve, non c'è un clone locale.
